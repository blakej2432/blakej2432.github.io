### n+1 문제란?

1번의 쿼리로 데이터베이스에서 N 개의 객체를 가져왔는데, 각 객체에 대해 추가적인 관련 데이터를 가져오기 위해 N번의 쿼리를 추가로 수행하는 상황

```python
# models.py
class Author(models.Model):
    name = models.CharField(max_length=100)

class Book(models.Model):
    title = models.CharField(max_length=100)
    author = models.ForeignKey(Author, on_delete=models.CASCADE)
```


이 때, book 에 해당하는 author name을 가져오고 싶으면

```python
# views.py
books = Book.objects.all()  # 1개의 쿼리 (전체 책 조회)

for book in books:
    print(book.author.name)  # 매 book마다 author 조회 쿼리 발생 → N번 쿼리 추가
```

    -> 결과적으로 N+1개의 쿼리가 발생하게 되고, 많은 쿼리로 성능 부하


### select_related 로 최적화
- Foreign Key, 1:1, 다:1 상황(다 쪽에서 1쪽 데이터를 가져오는 경우)에서 다른 연결된 테이블의 정보도 함께 가져올 때
- **한 개만 딸려오는 경우!**
- SQL의 SELECT ... JOIN 을 이용한다는 의미
- JOIN 을 활용해 한 번의 쿼리를 수행

```python
books = Book.objects.select_related('author')  # JOIN으로 book과 author 한 번에
for book in books:
    print(book.author.name)  # 추가 쿼리 발생 안함
```

### prefetch_related 로 최적화
- 1:다, 다:다 상황
- **여러개가 딸려오는 상황** -> 결과값 쿼리셋들의 리스트 !
- 장고는 두 번의 쿼리를 날리고, 파이썬으로 둘을 비교처리 (N+1번 쿼리보다 낫다!)
- prefetch는 "미리 가져온다"는 뜻. 파이썬이 메모리에서 조합한다.

```python
authors = Author.objects.all()  # 1쿼리

for author in authors:
    books = author.book_set.all()  #  작가마다 1쿼리 → 총 10쿼리 발생
```

```python
authors = Author.objects.prefetch_related('book_set')  # 두 쿼리 + 파이썬에서 매핑
for author in authors:
    print([book.title for book in author.book_set.all()])  # 추가 쿼리 없음
```

### prefetch 의 문제
- Django 가 쿼리 결과를 캐시로 보관하고 메모리에서 조합하므로<br> 데이터량이 많아지면 메모리 부담 커짐
- 다:1로 방향을 바꿔서 select_related 를 하거나
- 일부만 loading하여 pagination

```python
authors = Author.objects.prefetch_related('book_set')[:100]
```
